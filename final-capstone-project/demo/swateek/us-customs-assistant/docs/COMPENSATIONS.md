# What we did to compensate for a small model

The graded Track B section. One row per finding, from the first step: what broke, what fixed it, and the metric before and after. Carried-over lessons from the reference app (`../procurement-and-vendor-review/docs/small-model-log.md`) are marked "reference" until they are measured here.

| # | Date | Symptom | Compensation | Before → after | Evidence |
|---|---|---|---|---|---|
| 1 | 17 Nov | Reference: Qwen3 thinking mode multiplies output tokens (~14×) | Thinking off on every call (`chat_template_kwargs.enable_thinking=false`) | reference | `backend/src/customs/llm/endpoints.py` |
| 2 | 17 Nov | Reference: the token estimator under-counted tool prompts by ~40% | Calibrated estimator (+7 per message, +85 with tools), checked before every call | reference | `tests/test_token_estimate.py` |
| 3 | 17 Nov | Malformed JSON from the 8B model. **Measured:** the intake without a schema produced schema-valid JSON on the first try only **55%** of the time (80 scenarios); with strict `json_schema`, **100%**. Retries with the error fed back recovered every prompted case (0 left invalid). Field accuracy was the same either way (86.1% vs 85.8%). | Strict `json_schema` (constrained decoding) + Pydantic validation + 2 retries with the error fed back, then escalate | first-try valid 55% → 100%; extraction accuracy unchanged | `docs/results/week1-baselines.md` (intake rows) |
| 4 | 17 Nov | **The bare model can't do the money.** Closed-book and few-shot get the amount owed right on only 12–13% of answered turns; chain-of-thought and decomposition only 22%. Example A01 (gold $3.23): $108, $13.50, $22, $315. | All money from calculators over the signed-off rate tables; the writer refers to figures by handle and never types a number (SPEC §4) | amount accuracy 12–22% (baseline) → measured in the official runs | `week1_strategies.csv`, `week1_failures.csv` (`wrong_amount`) |
| 5 | 17 Nov | **Thinking harder invents more citations.** Citing a regulation section that isn't in the corpus: closed-book 5%, few-shot 5%, decomposition 16%, chain-of-thought 21%. Gold citation coverage is best with few-shot (74%) and worst with chain-of-thought (42%). | Citations only from clauses retrieved in the run (handles), fetch-by-id fallback (D20); the verifier blocks any other citation | invented citations 5–21% (baseline) → measured | `week1_failures.csv` (`invented_citation`) |
| 6 | 17 Nov | **Clarifying and scope judgement are unreliable.** Every strategy missed 10–11 of the 11 gold clarify turns ("no_clarify") and 2–3 out-of-scope cases; closed-book also asked unnecessary questions (8). | Clarify decided in code from the answer-changing facts table (`customs.tools.facts`); scope decided in code after intake | no_clarify 10–11 of 11 (baseline) → measured | `week1_failures.csv` |
| 7 | 17 Nov | **Few-shot is the best prompting strategy, and still far from usable.** Turn accuracy: few-shot 13.2%, CoT-SC 3.3%, closed-book 2.2%, decomposition 1.1%. CoT-SC costs 4× the tokens and 7× the latency of few-shot for less accuracy. | Few-shot examples (dev only) for the intake and writer prompts; no CoT on the default path | baseline turn accuracy 1–13% | `docs/results/week1-baselines.md` |
| 8 | 18 Nov | **Retrieval of a traveller's question misses the rule.** The question alone (wine, Paris, $90) found the gold clause in the top 5 for only 22% of claims (dev; frozen 25%). The reranker didn't fix that: the local MiniLM cross-encoder made it worse (dev R@1.5k 0.84 → 0.71), and Qwen3-8B listwise only improved ordering, at +1 call and ~4k tokens per search (dev R@1.5k 0.82). Listwise was run on dev only (45 calls); the frozen run (220 calls, ~880k tokens) was skipped because it couldn't change the decision. | Query built by code from the question + the calculators' rule names; topic filter from the rule's cites; 200-token windows, filled up to 1,500 tokens; no reranker; fetch-by-id fallback for any cited clause not retrieved (D20) | dev R@5 0.22 → 0.67, R@1.5k 0.36 → 0.84 (frozen R@5 0.25 → 0.69, R@1.5k 0.32 → 0.77) | `docs/results/retrieval-decisions.md`, `retrieval_experiment.md` |
| 9 | 18 Nov | **The intake mis-buckets trip length.** Given a string option (`"<48"`/`">=48"`) for `trip_hours`, Qwen3-8B chose `"<48"` for 6–10-day trips: 5 of 17 dev answers wrong. | Schema reshaped: `trip_hours` is a number; a separate yes/no is used only when no length is given; converted to the SPEC profile in code | dev amounts right 10/17 → 15/17 (dev-01 → dev-02) | `docs/results/dev-runs.md` |
| 10 | 18 Nov | **The intake invents scope flags and sanctions facts.** "Back from Dublin" was read as non-resident; "Havana Club" as made in Cuba (brand dropped); a Canadian province as the arrival state; cigars as cigarettes; "a 50 ml bottle" as 1 ml; a clarify reply as a new bottle. | Code grounding after the intake: scope flags need the traveller's quote; R12 brands named in the conversation are recorded; Cuban origin only if Cuba is mentioned; US state codes only; cigar/cigarette must match the words; an ml quantity below one container counts containers; facts-only replies merge into the existing line | dev clarify recall 1/3 → 3/3; facts invented 9 → 1 (dev-01 → dev-05) | `docs/results/dev-runs.md`, `customs/agent/intake.py` |
| 11 | 18 Nov | **Planner noise.** In most plans the planner attached `lines` to steps that take none, added the state lookup with no state, or left out the final search: 17 invalid plans and 12 router fallbacks in dev-01. | The validator repairs harmless extras and the always-last search (`plan_repaired`); missing, repeated or misordered calculators stay errors (planner once, then router) | router fallbacks 12 → 0 (dev-01 → dev-05) | `docs/results/dev-runs.md` |
| 12 | 18 Nov | **The writer invents handles when there are no figures** (prohibited-only answers): `[F1]` and years copied from OFAC text, which failed the verifier twice and escalated. | Prohibited-only answers use a code template (no writer call) | dev cuban_origin 1/3 → 3/3 | `docs/results/dev-runs.md` |
| 13 | 18 Nov | **One prompt line can break unrelated cases.** "List goods that are not alcohol or tobacco as `other`" made the model label wine and spirits `other` (dev 19/23 → 16/23). | Reverted; full dev reruns after every change, never failures-only reruns; agent frozen only after a clean confirmation run | dev 16/23 → 22/23 → 23/23 | `docs/results/dev-runs.md` |
