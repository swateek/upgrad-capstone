# Small-model log

A running record of where Qwen3-8B, or the harness around it, broke or cost too much, and what we did about it. It feeds the graded report section "What did we do to compensate for a small model?". Add an entry whenever a run teaches something. Link the raw result file.

| # | Date | Finding | Evidence | Compensation |
|---|---|---|---|---|
| 1 | 12 Nov | **Thinking mode is ON by default on SiliconFlow** and costs ~14× the output. The one-sentence answer was 612 completion tokens (568 of them reasoning) and 22.2 s, vs 41 tokens and 3.7 s with thinking off. Under an 8K window and a shared quota that is unaffordable on the default path. | `results/phase0-spike-siliconflow.json` checks 1–2 | The provider factory always sends `enable_thinking: false`. Thinking is turned on only in the chain-of-thought prompt experiment. |
| 2 | 12 Nov | **Native tool calling works** for a single tool. The model chose `screen_vendor`, the args were valid JSON matching the Pydantic schema, the `tool` role was accepted on the round trip, and the final answer kept the list name and snapshot date. | spike check 3 | Rely on native tool calls. Pydantic validation + one retry remains for when it fails. |
| 3 | 12 Nov | **`response_format: json_object` and strict `json_schema` both work**: schema-valid JSON, only the given citation id was used. Strict schema took 3.3 s. | spike checks 4–5 | Use strict `json_schema` (constrained decoding) for structured answers and critic verdicts. Pydantic validation + one retry stays as the safety net. Phase 3 compares schema-valid rates with and without it. |
| 4 | 12 Nov | **The token estimator under-counted tool prompts by ~40%** (128 estimated vs 212 actual), because Qwen's chat template adds ~85 tokens of tool instructions. Under-counting could let a call overflow 8K. | spike check 3 + `tests/test_token_estimate.py` | Calibrated `budget.py` (+7 per message, +85 when tools are present) so it errs slightly high. A test pins it to the measured values. |
| 5 | 12 Nov | **Deep Agents defaults spend 2,889 prompt tokens on the planner's first call**, before any retrieval. That's 35% of the 8K window, mostly the 7 filesystem tool schemas (2,830 tokens). Without filesystem it's still 1,790 (the long `write_todos` and `task` descriptions). | `results/phase0-deepagents-prompt-size.json` configs A, B | Build from `create_agent` + `TodoListMiddleware` + `SubAgentMiddleware` with short prompt and tool descriptions: **471 tokens** (config C), an 84% cut. |
| 6 | 12 Nov | **No 10-message cap in practice.** The API docs list `messages` as 1–10 items, but a 12-message history was accepted and answered correctly ("21" for note 3). Streaming works: first token in 1.2 s, 94 chunks in 4.6 s. (The first run of these checks hit 402 after ~1.3K tokens; the international site bills Qwen3-8B at 0.06/M tokens. They passed after a top-up.) | spike checks 6–7 | History length is limited only by the 8K token budget, not by message count. SSE streaming to the UI is viable. |
| 7 | 12 Nov | **Ungrounded answers hallucinate confidently.** Asked to "name three Indian procurement manuals" with no context, the model invented "PMGS", "PMCW" and "PMC". None of them exist. The real ones are the DoE manuals for goods, works, consultancy and non-consultancy services. | spike check 7 content | Policy answers come only from retrieved clauses. The critic rejects any factual sentence without a citation from the payload. Good material for the baseline failure note. |

## Harness facts worth remembering (deepagents 0.7.36)

- `create_deep_agent` no longer includes the todo-list middleware by default. Add `TodoListMiddleware` explicitly.
- `create_deep_agent` sets `recursion_limit` to **9,999**. The Track B 10-step cap has to come from our own step-cap middleware plus an explicit `recursion_limit` in the run config.
- `SubAgentMiddleware(task_description=...)` must keep the `{available_agents}` placeholder, or the model can't see which subagents exist.
