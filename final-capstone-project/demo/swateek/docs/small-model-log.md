# Small-model log

A running record of where Qwen3-8B, or the harness around it, broke or cost too much, and what we did about it. It feeds the graded report section "What did we do to compensate for a small model?". Add an entry whenever a run teaches something. Link the raw result file.

| # | Date | Finding | Evidence | Compensation |
|---|---|---|---|---|
| 1 | 12 Nov | **Thinking mode is ON by default on SiliconFlow** and costs ~14× the output. The one-sentence answer was 612 completion tokens (568 of them reasoning) and 22.2 s, vs 41 tokens and 3.7 s with thinking off. Under an 8K window and a shared quota that is unaffordable on the default path. | `results/phase0-spike-siliconflow.json` checks 1–2 | The provider factory always sends `enable_thinking: false`. Thinking is turned on only in the chain-of-thought prompt experiment. |
| 2 | 12 Nov | **Native tool calling works** for a single tool. The model chose `screen_vendor`, the args were valid JSON matching the Pydantic schema, the `tool` role was accepted on the round trip, and the final answer kept the list name and snapshot date. | spike check 3 | Rely on native tool calls. Pydantic validation + one retry remains for when it fails. |
| 3 | 12 Nov | **`response_format: json_object` and strict `json_schema` both work**: schema-valid JSON, only the given citation id was used. Strict schema took 3.3 s. | spike checks 4–5 | Use strict `json_schema` (constrained decoding) for structured answers and critic verdicts. Pydantic validation + one retry stays as the safety net. Phase 3 compares schema-valid rates with and without it. |
| 4 | 12 Nov | **The token estimator under-counted tool prompts by ~40%** (128 estimated vs 212 actual), because Qwen's chat template adds ~85 tokens of tool instructions. Under-counting could let a call overflow 8K. | spike check 3 + `tests/test_token_estimate.py` | Calibrated `budget.py` (+7 per message, +85 when tools are present) so it errs slightly high. A test pins it to the measured values. |
| 5 | 12 Nov | **Deep Agents defaults spend 2,889 prompt tokens on the planner's first call**, before any retrieval. That's 35% of the 8K window, mostly the 7 filesystem tool schemas (2,830 tokens). | 6 | 12 Nov | **No 10-message cap in practice.** The API docs list `messages` as 1–10 items, but a 12-message history was accepted and answered correctly ("21" for note 3). ## Phase 1 baseline: how the single-prompt model fails

Source: `results/phase1-baseline.json` and `.md`. The 25 policy questions (23 factual, 2 refusal), Qwen3-8B on SiliconFlow, thinking off, temperature 0, one call per question. "Gold" includes the verified alternate citations (`also_accept`) where a manual restates the same rule for the same scope.

| # | Date | Finding | Evidence | Compensation (planned) |
|---|---|---|---|---|
| 8 | 12 Nov | **Closed-book answers are confidently wrong, and the citations are invented.** Only 1/23 cited a real gold rule. Answers used well-formed but non-existent ids (`dfpr_2024:R3.2`, `gem_terms:4.2`, `gem:IM-P01`). `gfr_2017:R154` was used as a catch-all citation for unrelated facts (P-009, -010, -012, -021, -022). Wrong facts include bid security "1.5%" (rule: 2–5%), GeM payment "within 30 days" (rule: 10 days of CRAC), IM levels "Minor/Major/Critical" (rule: four levels incl. mild and serious), and **"rules do not prohibit bids from neighbouring countries"** (the rule requires DPIIT registration). It also invented a body, the "Department of Financial Programming and Reform". | closed_book rows | Never answer policy questions without retrieval. The critic rejects any citation not in this turn's payload. |
| 9 | 12 Nov | **Retrieval is the bigger bottleneck.** With BM25 top-5 pasted in, 15/23 answers cite a correct source. The gold source was retrieved for 18/23, so the model dropped or mis-cited it in 3 retrieved cases, and retrieval missed it in 5. | bm25_top5 rows | Phase 3: hybrid BM25 + dense with RRF, reranker, chunking experiment. Recall@k is measured separately (Track B). |
| 10 | 12 Nov | **The model rewrites citation ids.** It glued a GFR rule number onto a manual (`goods_manual_2024:R170`), attributed Make in India paragraphs to manual doc ids (`consultancy_manual_2025:5`, `works_manual_2025:6`), and added sub-clauses not in the index (`dfpr_2024:R11(2)`). 5/25 answers cite an id that was never retrieved, even when the facts in the sentence were right. | P-011, P-014, P-015, P-020 | Give each hit a short opaque handle ([1]..[5]) and map it back to the citation in code, or normalise and validate ids in the critic: strip sub-clauses, reject unknown ids, one revision. |
| 11 | 12 Nov | **Refusals fail once context is given.** With context, neither refusal case refused. For P-024 (June 2022 manual) it answered from the 2024 manual as if it were the 2022 one. For P-025 (debar a firm) it explained how to debar instead of declining. Closed-book declined one of the two. | P-024, P-025 | Refusal rules are checked in code before generation (intent check plus the domain's `refusals.yaml`), not left to the prompt. |
| 12 | 12 Nov | **Self-contradicting phrasing**: "Yes, the Make in India order does not apply…" (P-014). | P-014 bm25 | Structured answer schema (verdict field + cited sentences), tested in the Phase 3 prompt comparison. |

## Phase 3: where each prompting strategy breaks (13 Nov)

Source: `results/phase3-prompts.md` and `.json`. The 25 policy questions; the same top-5 sources for every strategy except decompose. Retrieval is not the limit: the gold source was in the shared top-5 for 23/23 factual questions.

| # | Strategy | How it breaks | Evidence |
|---|---|---|---|
| 22 | **plain** (numbered sources, cite [n]) | Strong baseline (21/23 correct source). Misses: it cites the general GFR 154 limit but not the scientific-department footnote limit (P-005), and cites the wrong source for the bid-security range (P-010). 4/25 answers carry an uncited sentence. | plain rows |
| 23 | **structured + few-shot** (JSON, prompted only) | 24/25 schema-valid. The one invalid reply stayed invalid after the validation error was fed back, so the retry path gained nothing here. It's the only strategy with **0 uncited sentences**: a source list per sentence forces grounding. It did not refuse the superseded-edition (P-024) or debar (P-025) requests; it set `refuse: false` and answered. | structured rows |
| 24 | **structured + constrained decoding** (`json_schema` strict) | **25/25 valid on the first try**: constrained decoding removes malformed JSON. Best refusal handling (missed only P-024). Constraining the shape didn't stop 4/25 answers putting facts in a sentence with an empty source list. | structured_strict rows |
| 25 | **chain-of-thought** (Qwen3 thinking on, reasoning hidden) | The only strategy citing a correct source on **23/23**. No reasoning leaked into the answer (0/25), but it is **5× slower** (18.8 s) and its answers sprawl: **10/25** carry uncited sentences, restating the reasoning as unsupported claims. Too slow for the 10-step agent loop. | cot rows |
| 26 | **decomposition** (plan ≤3 lookups, retrieve per lookup, answer) | **Worst** (14/23). The planned lookups are narrower than the question, so per-lookup top-3 retrieval often drops the passage the whole question would have found. 5 calls per question. All 25 plans were valid JSON; the failure is retrieval drift, not format. | decompose rows |

What the system uses: the agent's executor and `/answer` use the **plain** pattern with source handles (fast, 21/23, refs mapped in code). The two weaknesses the experiment exposed are covered in code: uncited sentences are caught by the deterministic critic, and refusals are decided before generation (refusal pre-check), not by the model. **Constrained decoding** is used wherever the system needs JSON, such as the critic verdict. The free-text refusal metric is a keyword heuristic that over-counts when an answer quotes "competent authority" (P-004, P-009, P-022); the structured strategies' refuse flag is exact.

## Phase 4: hardening (13 Nov)

| # | Date | Finding | Evidence | Compensation |
|---|---|---|---|---|
| 27 | 13 Nov | **The 8B executor's own search queries lose recall.** On the raw questions, hybrid + rerank found the gold passage in the top 5 for 23/23 factual questions. Inside the agent, the executor rewrites the question into its own search terms and misses passages the raw question finds. On a smoke question about the margin of purchase preference, the answer cited GFR 153 vaguely instead of stating 20%. | smoke run; 4-question e2e subset (P-016 labelled retrieval miss) | **Query anchoring** in code: every agent search also runs the user's original question, and both reranked lists are fused (RRF, top-5). | 28 | 13 Nov | **Malformed tool arguments.** LangChain already sends the validation error back to the model, and the 8B model did retry, but with no limit, and the failed call skipped our budgets and trace. | offline test with a scripted model | `ToolArgGuard` on the executor: the validation error goes back once per tool; a second malformed call is refused with a clear message. ## Ingest notes (12 Nov)

- The GFR PDF has no heading for **Rule 194**; it only appears in a cross-reference. It isn't in the index and the eval set doesn't ask about it.
- Footnotes (amendment history) are attached to **every rule on the same page**, so a rule's chunk can carry a neighbour's footnotes (e.g. Rule 154's scientific-department limit also appears on R151–R155). The eval gold cites only the rule the footnote belongs to.
- The PPP-MII PDF renders "Class-II" as "Class-I I". Retrieval still finds it; worth knowing when reading answers.

## Harness facts worth remembering (deepagents 0.7.36)

- `create_deep_agent` no longer includes the todo-list middleware by default. Add `TodoListMiddleware` explicitly.
- `create_deep_agent` sets `recursion_limit` to **9,999**. The Track B 10-step cap has to come from our own step-cap middleware plus an explicit `recursion_limit` in the run config.
- `SubAgentMiddleware(task_description=...)` must keep the `{available_agents}` placeholder, or the model can't see which subagents exist.
